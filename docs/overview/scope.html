01What Super Notes is

Super Notes keeps your notes in sync across your devices, and lets you chat with them. You ask a question in plain language. The answer is written from your own notes and points back to the notes it came from, so you can check it.

Who it is for
You first. Every note, search, chat, memory and file belongs to one user, and every query is limited to that user in the database.
Tech, in one line
Django 5.2 + DRF API, PostgreSQL 16 with pgvector, Celery and Redis, Vue 3 + TipTap web client, Google-only sign-in.
Where it runs today
On your machine, with fake AI providers. No hosting target and no real AI key yet.

06What we agreed

Your decisions, in plain words. The number is the entry in docs/DECISIONS.md.

Security

  • Security level is ASVS L2 (D6): security event trail, sign-in rate limits, strict headers, secrets scrubbed from logs, Dependabot.
  • Sign-in is Google only. No passwords. Google's own MFA protects the account.
  • Two devices per account at most.
  • PostgreSQL with pgvector is required; SQLite is not supported (D2).
  • Sync is based on revision numbers, not timestamps (D5).

Limits (D84, D91)

Two layers: a per-user limit and a system-wide limit, both editable in the admin without a deploy. Going over a limit blocks that feature only. Notes and sync keep working.

Behind-the-scenes model calls (condensing a follow-up, memory extraction) cost you nothing but are logged and capped by system limits.

Memory (D88, D94)

  • On by default, with a switch.
  • The app keeps telling you: a notice on your first open, then every 5 app opens until you choose.
  • You can see and delete every remembered fact.

Reminders (D87, D95)

  • A reminder has a due date and time, such as an expiry.
  • You get a daily heads-up for the 7 days before, then one on the due day: 8 in all.
  • Delivered by email and browser push.

Files (D85, D92)

  • Attachments live in S3 in production and on local disk in development.
  • PDF text is read with pypdf; streaming runs on uvicorn.

No stale JavaScript (D89)

  • The web client must never get stuck on old cached code: hashed file names, index.html never cached, a version check that prompts or forces a reload, and a service worker that never caches app code.

Lifecycle hooks (D90, D93)

  • Server hooks fire on every sign-in and on every app open or resume, so any feature can react without touching the sender.
  • "App open" means a real launch, or the first action after 5 idle hours.

Chat and clients

  • Chat history is kept until you delete it (D96).
  • Web uses vue-router and vitest (D86).
  • Android moves to V3; V2 ships as backend plus web (D566).

Working rules (D77)

  • master is released V1 and takes fixes only; v2 is the integration branch; one feature branch per phase, merged with --no-ff after review and green checks.
  • No new dependency without your approval. Commits carry your identity and no AI co-author lines.

07Pending on you

The code is done. These items need a decision, a key or your hands before V2 can be released as v2.0.0.

A. To get it live (backend + web)

  • A server blocks release
    Minimum 2 vCPU, 4 GB RAM, Ubuntu 24.04. Options: Oracle Cloud Always Free ARM (free, capacity often unavailable, card to verify) · Hetzner CX22, about €4–5 a month (recommended) · Contabo, about €5 for more RAM. One box runs Postgres, Redis, the API, the worker and the web files.
  • The domain to use blocks release
    Which subdomain, e.g. notes.yourdomain.com, and access to its DNS. Cloudflare's free DNS is simplest and gives HTTPS help.
  • AI keys: one embedding and one chat provider blocks release
    Cheapest start: Gemini's free tier for both. Or OpenAI embeddings (very cheap) with Claude Haiku. Until then everything runs on the built-in fake answers.
  • A Google OAuth web client id blocks release
    Free, in Google Cloud Console. Allowed origins: your domain and http://localhost:5173. Without it nobody can sign in.
  • File storage for attachments
    Cloudflare R2 is S3-compatible, free up to 10 GB and charges nothing for downloads, so it works with what is built. Or keep files on the server's disk until there are real users.
  • Email for reminders
    A free SMTP service (Brevo or Resend free tiers), or Gmail SMTP with an app password.
  • An admin email
    Where system alerts go, for example when a system-wide limit is reached.
Expected running cost: about ₹400–500 a month for the server, plus AI usage (a few dollars at personal scale). Storage, email, DNS and Google sign-in on free tiers. Prices as last known; check current ones.

08How the work is run

v2-feat/<item>-<slug> -> sub-tasks -> review -> merge --no-ff into v2 -> push -> tag
  • A main session conducts: it claims a queue item, splits it into sub-tasks and hands each to a sub-agent, picking a stronger model for subtle work (security, limits, concurrency) and a lighter one for routine work.
  • Every sub-agent result is read and checked before it is committed. Each reviewed sub-task is pushed at once, so a lost session costs one sub-task at most.
  • The docs are the source of truth. If it is not in docs/ and pushed, it did not happen.
  • Checks before any merge: backend tests, ruff, migrations check, OpenAPI schema validation, web build and tests.
